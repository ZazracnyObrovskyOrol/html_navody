SSH – kľúče, server a pripojenie

Kto generuje kľúče, kde ostáva privátny a kam ide verejný. Rozdiely medzi Linuxom a Windowsom, kopírovanie kľúčov, povolenie používateľov na serveri, prenos súborov a riešenie chýb.

Ako to funguje

SSH kľúč je pár dvoch súborov: privátny a verejný. Čo zamkne jeden, odomkne len druhý. Server si overí, že máš privátny kľúč, bez toho, aby ho niekedy videl.

💻 Tvoj počítač (klient)
Tu sa kľúč generuje príkazom ssh-keygen.
🔒 id_ed25519 – privátny, nikdy neopúšťa počítač
🔓 id_ed25519.pub – verejný, ten sa rozdáva
→kopíruje sa len

🖥️ Server / GitHub
Verejný kľúč sa pridá na koniec súboru
~/.ssh/authorized_keys používateľa, za ktorého sa prihlasuješ.
Na GitHube: Settings → SSH and GPG keys.
  • Kto generuje: vždy ten, kto sa bude pripájať (klient), na svojom počítači. Server kľúč negeneruje a nikdy ho nemá posielať e-mailom ani inak.
  • Privátny kľúč ostáva u teba v ~/.ssh/. Kto ho získa, prihlási sa za teba. Chráň ho heslom (passphrase).
  • Verejný kľúč môžeš pokojne ukázať komukoľvek. Na jeden server môžeš pridať kľúče z viacerých počítačov (každý na samostatný riadok).
  • Jeden kľúč na počítač je bežný postup. Keď počítač stratíš, zmažeš na serveroch len jeho riadok.
Server má vlastné kľúče (/etc/ssh/ssh_host_*), ktorými sa preukazuje on tebe. Pri prvom pripojení sa zobrazí otázka „Are you sure you want to continue connecting?“ – po potvrdení si klient odtlačok servera uloží do ~/.ssh/known_hosts a nabudúce kontroluje, či sa niekto nevydáva za server.

Generovanie kľúča

Príkaz je v Linuxe aj vo Windows rovnaký – Windows 10 a 11 majú OpenSSH klienta zabudovaného (spúšťa sa v PowerShelli alebo cmd).

Linuxterminál

ssh-keygen -t ed25519 -C "meno@pocitac"

WindowsPowerShell

ssh-keygen -t ed25519 -C "meno@pocitac"

Program sa spýta:

  1. Kam uložiť – Enter = predvolené ~/.ssh/id_ed25519. Ak už kľúč existuje, nič neprepisuj (odpovedz n) a zadaj iný názov.
  2. Passphrase – heslo k privátnemu kľúču. Odporúčané; aby si ho nezadával stále, použi ssh-agent.
ssh-keygen -t ed25519 -f ~/.ssh/id_server -C "pre domáci server"  # vlastný názov súboru
ssh-keygen -t rsa -b 4096 -C "meno@pocitac"     # RSA – len pre staré servery bez ed25519
ssh-keygen -p -f ~/.ssh/id_ed25519             # zmeniť / pridať passphrase
ssh-keygen -lf ~/.ssh/id_ed25519.pub           # odtlačok (fingerprint) kľúča

Zobraziť a skopírovať verejný kľúč

Linux

cat ~/.ssh/id_ed25519.pub
xclip -sel clip < ~/.ssh/id_ed25519.pub   # rovno do schránky

Windows

Get-Content $env:USERPROFILE\.ssh\id_ed25519.pub
Get-Content $env:USERPROFILE\.ssh\id_ed25519.pub | Set-Clipboard

Verejný kľúč je jeden riadok v tvare ssh-ed25519 AAAAC3Nz… meno@pocitac.

Nikdy neposielaj ani nekopíruj súbor bez .pub. Ak sa privátny kľúč dostal von, vygeneruj nový a starý zmaž zo všetkých serverov.

Ďalšie rozdiely:

  • Windows nemá príkaz ssh-copy-id – verejný kľúč sa kopíruje inak (viď nižšie).
  • Práva súborov: v Linuxe chmod, vo Windows ACL (icacls). Pri zlých právach SSH kľúč odmietne.
  • ssh-agent: v Linuxe sa spúšťa v relácii, vo Windows je to služba, ktorú treba raz zapnúť.
  • PuTTY používa vlastný formát .ppk – prevod cez PuTTYgen (Conversions → Import key). Pri zabudovanom OpenSSH to netreba.

Kopírovanie verejného kľúča na server

Cieľ: pridať obsah id_ed25519.pub na koniec ~/.ssh/authorized_keys na serveri. Prvýkrát sa ešte prihlasuješ heslom.

1Linuxssh-copy-id

ssh-copy-id meno@server                        # skopíruje id_ed25519.pub
ssh-copy-id -i ~/.ssh/id_server.pub meno@server # konkrétny kľúč
ssh-copy-id -p 2222 meno@server                # iný port

Sám vytvorí ~/.ssh na serveri a nastaví správne práva.

2WindowsPowerShell (na Linux server)

type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh meno@server "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"

Robí to isté ako ssh-copy-id. Na Windows server postup viď SSH server vo Windows.

3Ručne (keď nič iné nejde)

Skopíruj riadok z .pub do schránky, prihlás sa na server a vlož ho:

mkdir -p ~/.ssh && chmod 700 ~/.ssh
nano ~/.ssh/authorized_keys       # vlož riadok na koniec, ulož
chmod 600 ~/.ssh/authorized_keys

4Overiť

ssh meno@server                   # už sa nepýta heslo účtu (len passphrase kľúča)

GitHub

gh ssh-key add ~/.ssh/id_ed25519.pub -t "Notebook"  # cez gh, alebo na webe: Settings → SSH and GPG keys → New SSH key
ssh -T git@github.com                               # test: "Hi meno! You've successfully authenticated"
git remote set-url origin git@github.com:vlastnik/projekt.git  # prepnúť repozitár z https na ssh

Odobrať prístup kľúču

Na serveri zmaž príslušný riadok z ~/.ssh/authorized_keys (podľa komentára na konci riadku). Na GitHube kľúč zmaž v nastaveniach.

Práva súborov

SSH je prísne – ak má privátny kľúč alebo authorized_keys príliš voľné práva, kľúč sa ignoruje.

Linuxklient aj server

chmod 700 ~/.ssh
chmod 600 ~/.ssh/id_ed25519          # privátny kľúč
chmod 644 ~/.ssh/id_ed25519.pub
chmod 600 ~/.ssh/authorized_keys ~/.ssh/config
chown -R $USER:$USER ~/.ssh
chmod go-w ~                         # domovský adresár nesmie byť zapisovateľný pre iných

Windowsprivátny kľúč len pre teba

icacls $env:USERPROFILE\.ssh\id_ed25519 /inheritance:r
icacls $env:USERPROFILE\.ssh\id_ed25519 /grant:r "$($env:USERNAME):F"

Treba to napr. pri kľúči skopírovanom z iného disku, keď ssh hlási „UNPROTECTED PRIVATE KEY FILE“.

ssh-agent – passphrase len raz

Agent si pamätá odomknutý kľúč, takže passphrase zadáš raz za reláciu (alebo raz po prihlásení).

Linux

eval "$(ssh-agent -s)"     # spustiť agenta (desktopy ho väčšinou spúšťajú samy)
ssh-add                    # pridá id_ed25519, spýta sa na passphrase
ssh-add ~/.ssh/id_server   # iný kľúč
ssh-add -l                 # kľúče v agentovi
ssh-add -D                 # vyprázdniť agenta

WindowsPowerShell ako správca, raz

Get-Service ssh-agent | Set-Service -StartupType Automatic
Start-Service ssh-agent

Potom ako bežný používateľ:

ssh-add $env:USERPROFILE\.ssh\id_ed25519
ssh-add -l

Windows si kľúč pamätá aj po reštarte.

Automatické pridanie kľúča pri prvom použití – do ~/.ssh/config:

Host *
    AddKeysToAgent yes

Súbor ~/.ssh/config – skratky

Namiesto ssh -p 2222 -i ~/.ssh/id_server admin@192.168.1.50 stačí ssh domaci. Funguje rovnako v Linuxe aj vo Windows.

Host domaci
    HostName 192.168.1.50
    User admin
    Port 2222
    IdentityFile ~/.ssh/id_server
    IdentitiesOnly yes          # skúšať len tento kľúč

Host github.com
    User git
    IdentityFile ~/.ssh/id_ed25519

Host *
    AddKeysToAgent yes
    ServerAliveInterval 60      # udržať spojenie, aby nespadlo pri nečinnosti

Skratka funguje aj pre scp, rsync, git a VS Code Remote-SSH.

SSH server v Linuxe

Inštalácia a spustenie

sudo apt install openssh-server       # Debian, Ubuntu, MX Linux
sudo systemctl enable --now ssh       # systemd (Fedora/Arch: sshd)
sudo service ssh start                # sysvinit (napr. MX Linux v predvolenom režime)
sudo systemctl status ssh             # beží?
ip -br a                              # IP adresa, na ktorú sa pripájať

Firewall

sudo ufw allow ssh                    # port 22
sudo ufw allow 2222/tcp               # ak si zmenil port
sudo ufw status

Bezpečné nastavenie

Zmeny daj do vlastného súboru v /etc/ssh/sshd_config.d/ (pri aktualizácii sa neprepíše):

sudo nano /etc/ssh/sshd_config.d/10-moje.conf
PermitRootLogin no                # root sa priamo neprihlási
PasswordAuthentication no         # len kľúče – až keď kľúč funguje!
KbdInteractiveAuthentication no
PubkeyAuthentication yes
#Port 2222                        # iný port – menej automatických pokusov
sudo sshd -t                      # kontrola syntaxe – nič nevypíše = OK
sudo systemctl reload ssh         # alebo: sudo service ssh reload
Pred vypnutím hesiel over, že prihlásenie kľúčom funguje. Po zmene konfigurácie nezatváraj aktuálne pripojenie – otestuj prihlásenie v novom okne. Ak niečo nejde, v starom okne to ešte opravíš.

Povolenie používateľov cez SSH

Predvolene sa môže cez SSH prihlásiť každý používateľ systému, ktorý má heslo alebo kľúč (okrem roota, ak je PermitRootLogin no). Obmedzenie sa robí v sshd_config.

1Vytvoriť používateľa

sudo adduser jano                 # vytvorí účet, domovský adresár, spýta sa heslo
sudo usermod -aG sudo jano        # voliteľne: práva správcu (Fedora: skupina wheel)

2Dať mu kľúč

Jano vygeneruje kľúč u seba a pošle ti len .pub. Ty ho na serveri vložíš:

sudo install -d -m 700 -o jano -g jano /home/jano/.ssh
sudo nano /home/jano/.ssh/authorized_keys          # vlož jeho verejný kľúč
sudo chown jano:jano /home/jano/.ssh/authorized_keys
sudo chmod 600 /home/jano/.ssh/authorized_keys

3Povoliť len vybraných

V /etc/ssh/sshd_config.d/10-moje.conf zvoľ jeden spôsob:

AllowUsers admin jano             # len títo používatelia (ostatní sú odmietnutí)
AllowUsers jano@192.168.1.*       # jano len z lokálnej siete
AllowGroups sshusers              # alebo: len členovia skupiny
DenyUsers test                    # zakázať konkrétneho

Pri skupine:

sudo groupadd sshusers
sudo usermod -aG sshusers jano
sudo usermod -aG sshusers admin   # nezabudni na seba!
sudo sshd -t && sudo systemctl reload ssh

4Výnimky pre jedného používateľa

Match User zaloha                 # musí byť na konci súboru
    PasswordAuthentication no
    AllowTcpForwarding no
    X11Forwarding no

Zablokovať alebo odobrať prístup

sudo usermod -L jano                       # zamknúť heslo (kľúč by ešte fungoval)
sudo usermod -s /usr/sbin/nologin jano     # zakázať prihlásenie úplne
sudo rm /home/jano/.ssh/authorized_keys    # zmazať jeho kľúče
who                                        # kto je práve prihlásený
last -n 20                                 # história prihlásení
sudo journalctl -u ssh -n 50               # záznam SSH servera (inak /var/log/auth.log)

SSH server vo Windows

Windows 10/11 a Windows Server majú OpenSSH server ako voliteľnú súčasť. PowerShell ako správca:

Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
Start-Service sshd
Set-Service -Name sshd -StartupType Automatic
Get-NetFirewallRule -Name *ssh*        # inštalácia pridá pravidlo pre port 22

Kam dať verejný kľúč

  • Bežný používateľ: C:\Users\meno\.ssh\authorized_keys
  • Člen skupiny Administrators: C:\ProgramData\ssh\administrators_authorized_keys – súbor v profile sa pre adminov ignoruje.
# pre administrátora (PowerShell ako správca)
Add-Content C:\ProgramData\ssh\administrators_authorized_keys "ssh-ed25519 AAAA… meno@pocitac"
icacls C:\ProgramData\ssh\administrators_authorized_keys /inheritance:r /grant "Administrators:F" /grant "SYSTEM:F"

Povolenie používateľov

V C:\ProgramData\ssh\sshd_config fungujú tie isté voľby (AllowUsers, AllowGroups, PasswordAuthentication). Mená sa píšu malými písmenami, doménové ako domena\meno.

Restart-Service sshd

Predvolený shell po prihlásení je cmd. Zmena na PowerShell:

New-ItemProperty -Path "HKLM:\SOFTWARE\OpenSSH" -Name DefaultShell -Value "C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe" -PropertyType String -Force

Prenos súborov

scp subor.txt meno@server:/home/meno/          # na server
scp meno@server:/var/log/syslog .              # zo servera do aktuálneho adresára
scp -r adresar/ meno@server:~/zaloha/          # celý adresár
scp -P 2222 subor.txt meno@server:~            # iný port (veľké P)
scp subor.txt domaci:~                         # so skratkou z ~/.ssh/config
rsync -avz --progress adresar/ meno@server:~/zaloha/   # Linux: prenesie len zmeny
rsync -avz --delete adresar/ domaci:~/zaloha/          # zrkadlo – zmaže aj, čo u teba už nie je
sftp meno@server          # interaktívne: ls, cd, get subor, put subor, exit

Graficky: vo Windows WinSCP alebo FileZilla (protokol SFTP), v Linuxe správca súborov – do adresy zadaj sftp://meno@server/.

Tunely a skok cez server

ssh -L 8080:localhost:80 meno@server     # http://localhost:8080 u teba = port 80 na serveri
ssh -L 5432:db.lan:5432 meno@server      # prístup k stroju za serverom
ssh -R 9000:localhost:3000 meno@server   # opačne: port 9000 na serveri = tvoj port 3000
ssh -D 1080 meno@server                  # SOCKS proxy – prehliadač ide cez server
ssh -N -L 8080:localhost:80 meno@server  # len tunel, bez príkazového riadku
ssh -J brana meno@vnutorny               # pripojenie cez prechodný server (jump host)

V config sa skok zapíše ako ProxyJump brana.

Príkaz na serveri bez prihlásenia do shellu

ssh domaci "df -h"                       # spustí príkaz a skončí
ssh -t domaci "sudo apt update"          # -t pre príkazy, ktoré sa pýtajú heslo

Riešenie chýb

ssh -v meno@server        # podrobný výpis – ukáže, ktoré kľúče skúša a prečo zlyhá (-vvv ešte viac)
