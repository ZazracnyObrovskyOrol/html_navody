Git a GitHub – príkazy

Prehľadný ťahák: stiahnuť zmeny, upraviť, commitnúť a pushnúť. K tomu vetvy, pull requesty a oprava bežných chýb.

Základný scenár: pull → úpravy → commit → push

git pull→úpravy→git add→git commit→git push

1Stiahnuť najnovšie zmeny

Vždy začni tým, že si stiahneš, čo medzitým pribudlo na GitHube.

git status             # musí byť čisto: "nothing to commit"
git pull

2Urobiť úpravy

Uprav súbory v editore. Potom sa pozri, čo sa zmenilo:

git status             # ktoré súbory sú zmenené / nové
git diff               # čo presne sa zmenilo (riadok po riadku)

3Pripraviť zmeny na commit

git add subor.html     # konkrétny súbor
git add .              # všetko v aktuálnom adresári
git diff --staged      # kontrola, čo pôjde do commitu

4Commit

git commit -m "Krátky popis, čo a prečo sa zmenilo"

Správu píš v rozkazovacom/opisnom tvare, napr. „Pridaná stránka s Git príkazmi“.

5Push na GitHub

git push

Ak push zlyhá s rejected … fetch first, niekto medzitým pushol. Urob git pull a potom znova git push.

Celé naraz (keď vieš, čo robíš): 
git pull
# … úpravy …
git add .
git commit -m "Popis zmeny"
git push

Stav a história

git status                     # čo je zmenené, na akej vetve som
git log --oneline -10          # posledných 10 commitov
git log --oneline --graph --all # história so všetkými vetvami
git show                       # detail posledného commitu
git show abc1234               # detail konkrétneho commitu
git diff                       # neuložené zmeny (ešte bez add)
git diff --staged              # zmeny pripravené na commit

Overiť zmeny pred pullom

git pull = git fetch + zlúčenie. Ak chceš najprv vidieť, čo prichádza, rozdeľ to na dva kroky:

git fetch                          # stiahne info, nič nemení v súboroch
git status                         # "behind by 3 commits" = 3 nové commity
git log --oneline HEAD..origin/main # aké commity prídu
git diff HEAD origin/main          # aké zmeny v súboroch prídu
git pull                           # až potom stiahnuť

Ak máš rozpracované zmeny a chceš pullnúť, odlož ich bokom:

git stash          # odloží neuložené zmeny
git pull
git stash pop      # vráti ich späť

Čistejšia história bez „merge“ commitov:

git pull --rebase

Vetvy

Vetva = samostatná línia práce. Na main nechaj funkčný stav, nové veci rob vo vetve.

Vytvoriť vetvu a pracovať v nej

git switch main
git pull                           # začni z aktuálneho main
git switch -c nova-funkcia         # vytvorí vetvu a prepne sa do nej
# … úpravy, add, commit …
git push -u origin nova-funkcia    # prvý push vetvy (-u ju prepojí s GitHubom)
git push                           # ďalšie pushe už stačí takto

Prehľad a prepínanie

git branch             # lokálne vetvy (* = aktuálna)
git branch -a          # aj vetvy na GitHube
git switch main        # prepnúť sa na existujúcu vetvu
git switch nazov       # stiahne a prepne aj vetvu, ktorá je len na GitHube

Zlúčiť vetvu do main (bez pull requestu)

git switch main
git pull
git merge nova-funkcia
git push

Zmazať vetvu

git branch -d nova-funkcia             # lokálne (len ak je zlúčená)
git push origin --delete nova-funkcia  # na GitHube
git fetch --prune                      # upratať odkazy na zmazané vetvy

Pull request (GitHub)

Pull request (PR) = žiadosť o zlúčenie vetvy do main s možnosťou kontroly. Príkazy nižšie používajú nástroj gh; to isté sa dá robiť aj na webe GitHubu.

Vytvoriť PR

git push -u origin nova-funkcia
gh pr create --fill                    # názov a popis z commitov
gh pr create --title "Názov" --body "Popis"
gh pr create --web                     # otvorí formulár v prehliadači

Preveriť cudzí PR

gh pr list                     # otvorené pull requesty
gh pr view 12                  # popis a stav PR č. 12
gh pr diff 12                  # zmeny v PR
gh pr checkout 12              # stiahne PR lokálne – dá sa vyskúšať
gh pr checks 12                # výsledky automatických testov
git switch main                # po skúšaní späť na main

Schváliť a zlúčiť

gh pr review 12 --approve
gh pr review 12 --request-changes -b "Prosím oprav …"
gh pr merge 12 --squash --delete-branch    # zlúči a zmaže vetvu
git switch main && git pull                # stiahni zlúčený výsledok

Riešenie konfliktov

Konflikt vznikne, keď ty aj niekto iný zmeníte ten istý riadok. Git to oznámi pri pull alebo merge.

git status                 # "both modified" = súbory s konfliktom

V súbore nájdeš značky – nechaj správnu verziu a značky zmaž:

<<<<<<< HEAD
moja verzia
=======
verzia z GitHubu
>>>>>>> origin/main
git add subor.html         # označí konflikt ako vyriešený
git commit                 # dokončí merge (pri rebase: git rebase --continue)
git push

Ak sa chceš vrátiť pred pokus o zlúčenie: git merge --abort (alebo git rebase --abort).

Oprava chýb

SituáciaPríkaz
Zahodiť zmeny v súboregit restore subor.html
Zrušiť git addgit restore --staged subor.html
Opraviť správu posledného commitugit commit --amend -m "Nová správa"
Pridať zabudnutý súbor do posl. commitugit add subor → git commit --amend --no-edit
Zrušiť posledný commit, zmeny ponechaťgit reset --soft HEAD~1
Vrátiť commit, ktorý už je na GitHubegit revert abc1234 → git push
Odložiť rozpracované zmenygit stash / git stash pop
Commit omylom na main namiesto vetvygit switch -c nova-vetva → git switch main → git reset --hard origin/main
--amend a reset používaj len na commity, ktoré ešte nie sú pushnuté. git reset --hard nenávratne zmaže necommitnuté zmeny.

Prvé nastavenie

git config --global user.name "Meno"
git config --global user.email "meno@example.com"
git config --global init.defaultBranch main
git config --global pull.rebase false     # pull robí merge (predvolené správanie)

gh auth login                             # prihlásenie do GitHubu pre gh aj git push

Stiahnuť existujúci projekt

git clone https://github.com/vlastnik/projekt.git
cd projekt

Nový projekt na GitHub

git init
git add .
git commit -m "Prvý commit"
gh repo create projekt --private --source=. --push

Prepojiť s už existujúcim repozitárom na GitHube

git remote add origin https://github.com/vlastnik/projekt.git
git push -u origin main
git remote -v              # kontrola, kam sa pushuje
